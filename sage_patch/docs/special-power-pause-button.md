# Grey paused SpecialPower CommandButtons

`special-power-pause-button` is a UI-only patch for RotWK `2.01.2614.37001`.
After a failed `isReady()` check, a positive pause count produces the existing
disabled availability status `0`, so the ControlBar draws the button grey.
Unpaused cooldowns retain their native progress display and status calculation.
Ready powers continue through the original ready branch.

This is an independently selectable companion to
[experience-level-down](experience-level-down.md),
[upgrade-module-removal](upgrade-module-removal.md), and
[experience-xp-cap](experience-xp-cap.md). It adds no INI parameters and does not
replace or change XP, level, upgrade-removal, Permanent, pause/resume or readiness
hooks. `UnpauseSpecialPowerUpgrade` still uses its native removal implementation
to call `pauseCountdown(TRUE)`.

## Evidence and hook

The user observed a paused power with pause count `1` and `isReady() == false`.
The availability evaluator returned `5`; changing that result to `0` in Cheat
Engine made the same button grey. This is evidence for the status choice, not
an in-game test of the generated patch.

All addresses below were checked against the supplied original
`tools/BFME-FILES/game.dat.backup`. They are VAs, mapped through the PE section
table with `file_offset`.

| Address | Role |
| --- | --- |
| `0x00942733` | ControlBar command availability evaluator |
| `0x0094357A` | Virtual `isReady()` call, test and ready branch |
| `0x00943585` | Seven-byte hook window after the not-ready result |
| `0x0094358C` | Resume native x87 cooldown processing |
| `0x009438C8` | Existing `XOR EAX,EAX; JMP 0x00942C60` disabled path |
| `0x00942C60` | Native register/SEH/stack epilogue, `ret 0x14` |

The original hook bytes are **`8B 06 8B CE FF 50 08`**:

```asm
mov eax, [esi]
mov ecx, esi
call dword ptr [eax+08h]  ; getPercentReady(), float in ST(0)
```

They become `E9 <rel32> 90 90` to an allocated `.sppause` section. The cave uses
the existing allocator and is executable/readable, code-only, with no runtime
writes. Its address and relative displacement depend on earlier patches.

The UI obtains ESI through the object's native SpecialPower lookup. This can
return either of the two interface layouts already documented in
[description-timers](description-timers.md):

| Interface family | Identifying `startPowerRecharge` slot `+0x3C` | Pause counter |
| --- | --- | --- |
| Ordinary SpecialPower interface, module `+0x10` | `0x00896E31` | interface `+0x0C` |
| SpecialPowerUpdate interface, module `+0x24` | `0x00991500` | interface `+0x08` |

The supplied example vtable `0x00C73890` uses the first layout. The second layout
also reaches this availability path; reading its `+0x0C` as a counter would read
a timestamp and could incorrectly disable an ordinary cooldown. The cave selects
the confirmed offset by the existing recharge slot. Unknown layouts retain the
original percentage path. No heap address, power enum or CommandButton is hard-coded.

On a positive counter, the cave jumps directly to `0x009438C8`. It neither calls
the percentage getter nor pushes or pops x87 values. Otherwise it executes the
seven displaced bytes exactly once and resumes at `0x0094358C`, where the original
code consumes the float. The cave touches only the original caller-saved EAX/ECX
registers and flags; callee-saved registers, stack and SEH cleanup remain native.

Every edited byte and preserved ABI anchor is checked before allocation or writing.
The fingerprints cover the preceding readiness branch, cooldown body, disabled
path, epilogue, both layout readers/recharge entries and representative native
vtables. Existing gameplay readiness hooks are outside these windows. Unexpected
bytes fail before mutation. A pre-existing `.sppause` rejects reapplication;
verification checks the entire cave, hook and untouched anchors.

## Applying it in the level-down workflow

From the repository, with Python 3.13 and the four-patch binary generated by the
previous follow-up:

```powershell
New-Item -ItemType Directory -Force tools/BFME-FILES/experience-ui-fix
.venv\Scripts\python.exe -m sage_patch apply special-power-pause-button --in tools/BFME-FILES/experience-follow-up/game.dat --out tools/BFME-FILES/experience-ui-fix/game.dat
.venv\Scripts\python.exe -m sage_patch verify special-power-pause-button tools/BFME-FILES/experience-ui-fix/game.dat
.venv\Scripts\python.exe -m sage_patch verify experience-level-down tools/BFME-FILES/experience-ui-fix/game.dat
.venv\Scripts\python.exe -m sage_patch verify upgrade-module-removal tools/BFME-FILES/experience-ui-fix/game.dat
.venv\Scripts\python.exe -m sage_patch verify experience-xp-cap tools/BFME-FILES/experience-ui-fix/game.dat
.venv\Scripts\python.exe -m sage_patch verify level-grant-special-power-negative-experience tools/BFME-FILES/experience-ui-fix/game.dat
```

It can also be applied to a clean supported binary by itself. Python callers can
add `SpecialPowerPauseButtonPatch()` before or after the existing companions;
the existing requirement to apply the XP cap after level-down remains unchanged.

## Automated and in-game validation

Python 3.13 tests check original signatures, atomic rejection, registration and CLI,
the sole changed instruction window, relative targets, complete displaced instructions,
reapplication and tamper detection. Capstone decodes the entire cave. Unicorn
executes the native UI readiness prelude, cooldown/status calculation, disabled
return and SEH epilogue. It checks both counter offsets, zero/positive/nested/negative
counts, ready-branch bypass, unknown-layout fallback and unchanged unpaused progress.
Both paths preserve a pre-existing x87 value as well as stack and saved registers.

The lifecycle fixture executes native XP loss, reversible upgrade removal,
UnpauseSpecialPowerUpgrade, pause/resume and readiness. Percentage values and
subsequent ready-branch conditions are modeled. Real-binary tests apply all five
patches with the UI patch first or last and verify every patch and the unchanged backup.

No in-game test of this binary patch has been performed. Test in RotWK:

1. Select a hero whose SpecialPower is initially locked by a missing OBJECT upgrade.
2. Level up to unlock it and check that the button becomes active.
3. Use the power and confirm the normal cooldown display.
4. Drain XP until its upgrade is lost through level-down.
5. Confirm a grey disabled button and rejection of actual activation.
6. Level up again and verify unlocking and the expected remaining cooldown.

Repeat with `Permanent = Yes`, nested pauses, SpecialPowerUpdate behaviors, shared
timers, multiple selection and another source of pause/resume. The patch intentionally
greys any not-ready power with a positive known-layout pause counter, including
`StartsPaused` and pauses unrelated to level-down. It does not distinguish pause
sources or change cooldown timing. Check that those other pause mechanisms' button
presentation is appropriate for the mod. Rendering, custom interfaces, selection
aggregation, save/load, replays and multiplayer remain in-game validation items.
